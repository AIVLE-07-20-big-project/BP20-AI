# 고객 대응방안 추천 및 검증 에이전트

## 개요

상권·업종·시점별 매출 데이터를 바탕으로 매출 하락 위험과 문제 유형을 진단하고, 실행 가능한 대응방안을 추천한다. 추천 전에는 과거 실행 로그로 정책을 평가하고, 추천 후에는 외부 근거와 실행 후 지표를 통해 결과를 검증한다.

## 입력과 출력

- **입력**: 상권, 업종, 기준 시점, 매출·방문·고객·상권 지표
- **처리**: 위험 진단 → 문제 유형 분류 → 후보 방안 생성 → 정책 안전성 평가 → 대응방안 선택 → 근거 기반 리포트 생성
- **출력**: 위험도, 문제 유형, 추천 방안, 정책 평가 결과, 외부 근거, 실행 순서, 실행 후 확인 지표

## 전체 작동 흐름

1. **위험 진단**: 시간에 따라 변하는 매출·상권 지표를 이용해 매출 하락 위험을 추정한다.
2. **문제 유형 분류**: 수요 이탈, 차별화 필요, 강점 확대 등 현재 상황에 맞는 처방 유형을 정한다.
3. **후보 방안 구성**: 문제 유형별로 실행 가능한 대응방안을 구성한다.
4. **정책 평가**: 과거 실행 로그를 이용해 후보 방안의 예상 보상과 안전성을 평가하고, 기준에 미달하는 방안은 제외한다.
5. **방안 선택**: 학습된 Contextual Bandit을 사용하되, 학습 데이터가 부족하면 사전 우선순위 기반으로 대체한다.
6. **근거 기반 리포트**: 선택된 방안에 관련된 외부 근거와 매장 진단 결과를 결합해 실행 계획을 작성한다.
7. **효과 검증**: 실행 후 POS 지표와 비교·대조 분석을 이용해 실제 효과를 별도로 확인한다.

## LangGraph 기반 에이전트 구조

각 단계를 독립된 노드로 구성하고, 검증 결과에 따라 다음 단계를 결정한다.

> **실제 LangGraph 다이어그램 이미지 삽입 위치**

```text
진단
 ↓
후보 방안 생성
 ↓
OPE 안전성 검증
 ↓
방안 선택
 ↓
효과 추정 · RAG 근거 검색
 ↓
사용자 승인

※ 기준 미달 시 방안 선택 단계로 제한적 재진입
```

LangGraph는 진단·추천·검증·승인·리포트 생성을 하나의 상태 흐름으로 연결한다. 사용자가 방안을 수정하거나 승인하면 최종 선택 방안 기준으로 효과 추정과 근거 검색을 다시 수행한다.

## RAG 작동 방식

RAG는 대응방안을 결정하는 모델이 아니라, 선택된 방안을 설명할 외부 근거를 검색해 리포트의 신뢰성을 높이는 보조 과정이다.

### 근거 자료와 전처리

공공·공식 보고서, 학술 연구, 플랫폼·업계 자료를 수집해 근거 데이터베이스를 구성했다. 긴 문서는 약 900자 단위로 나누고, 청크 사이에 150자를 중첩했다. 각 청크에는 자료 유형, 대응방안 분야, 출처, 페이지, 수치 포함 여부를 함께 저장했다.

### 벡터화와 검색

각 청크를 다국어 임베딩 모델 `BAAI/bge-m3`로 벡터화했다. 선택된 대응방안과 대응방안 분야를 기준으로 관련 자료를 검색하고, 검색 결과를 방향성 근거와 수치 근거로 나눈다. 방향성은 학술 자료에서, 수치 참고값은 플랫폼·업계 자료에서 우선 수집하며, 대응방안과 직접 관련된 자료를 우선한다.

### 생성과 검증

검색된 근거와 매장 진단 결과를 생성 모델에 제공해 대응방안의 이유, 실행 순서, 확인 지표를 작성한다. 검색 결과에 없는 수치·출처는 생성하지 않으며, 외부 자료의 수치는 해당 매장의 실측 효과가 아닌 참고값으로 표시한다. 근거가 부족하면 수치 없이 방향성만 설명한다.

> **RAG 처리 순서**: 자료 수집 → 청킹 → 벡터화 → 관련 근거 검색 → 리포트 생성 → 수치·출처 검증

## 모델 선택과 검증

### 위험 진단 — Cox 시변 생존모형

매장별 관찰기간과 상권 지표의 변화가 다르므로 시간에 따른 변화를 반영할 수 있는 Cox 시변 생존모형을 사용한다.

- 표본 19,921개, 매출 20% 이상 하락 이벤트 4,591건
- C-index **0.9138**
- 위험 최저 분위 생존율 **99.08%**, 최고 분위 **19.14%**

위험도가 높아질수록 실제 생존율이 낮아져 위험 순위와 실제 결과의 일관성을 확인했다.

### 대응방안 추천 — Neural Contextual Bandit

상권·업종·시점에 따라 최적 방안이 달라지고 정답 라벨이 없으므로 Contextual Bandit을 사용한다. 실행 로그가 부족한 문제 유형은 사전 우선순위 기반으로 대응한다.

합성환경 평가에서 후보 정책은 0.0863, 균등 기준정책은 0.0382의 정책 가치를 보였다. 절대 개선폭은 **+0.0481**이었고, 3개 seed 모두에서 기준정책보다 높은 결과를 확인했다.

### 정책 평가 — OPE

실행 전에 과거 로그만으로 후보 정책을 평가하기 위해 IPS·SNIPS·DR을 사용한다. DR은 보상 모델과 가중치 추정을 함께 사용해 IPS 단독보다 분산을 줄이는 방식이다.

- OPE: 실행 전 과거 로그 기반 정책 평가
- SCM: 실행 전후 또는 유사 대조군 기반 효과 추정
- 실제 실행 가능성이 낮거나 기준 정책보다 불리한 후보는 추천에서 제외

## 검증 결과 요약

| 구성 요소 | 대표 지표 | 결과 | 해석 |
|---|---|---:|---|
| Neural Contextual Bandit | 정책 가치 | 0.0863 | 합성환경의 균등 기준정책 0.0382보다 높음 |
| Neural Contextual Bandit | 기준 대비 절대 개선폭 | **+0.0481** | 3개 seed 모두 기준정책보다 높음 |
| OPE | DR 정책 가치 | 0.0642 / 0.1373 | 기준정책 대비 개선으로 **추정**됨: +0.0077 / +0.0878 |
| SCM | 추정·관측 변화 | +18.61% / +5.02% | 대조군 30개·실측 사례 4건 기반의 탐색적 결과 |

Neural Contextual Bandit 결과는 실제 매장 성능이 아니라 알려진 보상함수를 사용한 합성환경 결과다. OPE는 과거 로그를 이용한 정책 가치 추정이며, SCM 결과는 표본이 제한된 탐색적 효과 추정·관측이다. 따라서 세 결과 모두 실제 정책의 인과적 효과를 확정하는 근거는 아니며, 실행 후 추가 검증이 필요하다.

## 효과 검증 예시

합성 POS 데이터에서 타임세일 적용 전후를 비교한 결과, 목표 시간대 매출은 **+39.5%**, 전체 매출은 **+9.1%**, 방문 건수는 **+5.5%** 변화했다. 이는 효과검증 파이프라인의 동작 예시이며, 특정 매장에 대한 인과적 효과를 의미하지 않는다.

## 신뢰성 확보 장치

- RAG 검색 결과에 없는 수치와 출처는 최종 리포트에 사용하지 않는다.
- 외부 문헌 수치와 매장 실측 수치를 구분해 표시한다.
- 합성 데이터 결과는 실제 성능이나 실제 정책 효과로 보고하지 않는다.
- OPE 기준을 통과하지 못한 후보는 제외하고, 필요할 때만 제한적으로 재선택한다.
- 최종 효과는 실행 후 POS 지표와 별도의 효과검증 결과로 판단한다.
